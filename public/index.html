METHODOLOGY

How DLKS-MQTT Works

01

Ephemeral Key Generation

A Linear Congruential Generator (LCG) produces a unique 128-bit session key K_sess for every connection — no key reuse, ever.

02

Minimalistic Handshake

Security is embedded directly into standard MQTT CONNECT and CONNACK messages, adding zero extra round-trips.

03

Cryptographic Integrity

BLAKE2s hashing verifies data integrity per message. Encrypted payloads ensure confidentiality throughout the session.

PROTOCOL FLOW

3-Step Handshake

📡

Device Initiation

The device sends a CONNECT message carrying K_sess, its unique device ID (ID_dev), and a random Nonce (N) to block replay attacks.

↓
🛡️

Broker Verification

The broker decrypts the payload, validates the nonce, and authenticates the device against its known identity.

↓
✅

Session Establishment

The broker replies with a modified CONNACK including authentication status and a timestamp — secure channel is live.
